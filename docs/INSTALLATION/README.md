# دليل التثبيت — نظام التدبير المادي (مدرسة حسان بن ثابت)

النظام **خادم مركزي واحد** للمؤسسة، تحفظ فيه كل البيانات. يصل إليه المستخدمون بإحدى الطرق الثلاث:

| الطريقة | ما يحتاجه المستخدم | ملاحظات |
|---|---|---|
| المتصفح / PWA | Chrome أو Edge أو Firefox | مع HTTPS يمكن «تثبيت» التطبيق وفتح الواجهة دون اتصال |
| تطبيق Windows | `HassanAssets-Setup-1.0.0.exe` | Windows 10/11 (64 بت) |
| تطبيق Android | `HassanAssets-1.0.0.apk` | Android 7.0 فما فوق |

تطبيقا Windows وAndroid **واجهتان للخادم**. لا يحفظان بيانات المؤسسة على الجهاز، بل عنوان الخادم فقط. يحتاجان إلى الوصول إلى الخادم (شبكة المؤسسة أو الإنترنت).

---

## 1. تثبيت الخادم

### المتطلبات
- حاسوب أو خادم يعمل باستمرار: Linux (يوصى بـ Ubuntu 22.04 أو 24.04)، أو Windows 10/11 مع Docker Desktop.
- معالج بنواتين على الأقل، وذاكرة 4 GB، و20 GB من التخزين على الأقل (والنسخ الاحتياطية تحتاج مساحة إضافية).
- Docker Engine مع Docker Compose v2 (الأمر `docker compose version` يعمل).
- اتصال بالإنترنت **عند التثبيت فقط**، لتنزيل الصور والحزم.

### الخطوات
```bash
# 1) انسخ مجلد المشروع إلى الخادم، ثم:
cd hassan-assets-management
cp .env.example .env

# 2) ولّد الأسرار وضعها في .env (لا تشاركها ولا تضعها في Git)
openssl rand -hex 16   # ← POSTGRES_PASSWORD
openssl rand -hex 32   # ← JWT_ACCESS_SECRET
openssl rand -hex 32   # ← JWT_REFRESH_SECRET
openssl rand -base64 32  # ← BACKUP_ENCRYPTION_KEY (احفظ نسخة منه خارج الخادم)
```
في `.env` اضبط أيضاً:
- `WEB_ORIGIN`: العنوان الذي يفتحه المستخدمون، مثل `http://192.168.1.10:8080` أو `https://assets.example.ma`.
- `WEB_PORT`: منفذ الواجهة (افتراضياً 8080).
- `COOKIE_SECURE`: `true` مع HTTPS، و`false` على شبكة محلية عبر http.
- `SETUP_TOKEN` (اختياري، يوصى به إن كان الخادم مكشوفاً على الإنترنت): رمز يُطلب في شاشة الإعداد الأول.
- `BACKUP_DAILY_HOUR` (اختياري): ساعة النسخ الاحتياطي اليومي التلقائي (0 إلى 23).

```bash
# 3) البناء والتشغيل (أول مرة: 5 إلى 15 دقيقة)
docker compose -f docker/docker-compose.yml --env-file .env up -d --build

# 4) التحقق
docker compose -f docker/docker-compose.yml --env-file .env ps
curl http://localhost:8080/api/v1/health      # ← {"status":"ok"}
```
5) افتح `http://<عنوان-الخادم>:8080` من المتصفح. تظهر شاشة **الإعداد الأول** لإنشاء حساب مدير النظام، ثم أدخل معلومات المؤسسة من الإعدادات.

عند كل تشغيل، يطبّق الخادم تلقائياً ترحيلات قاعدة البيانات الجديدة دون حذف أي بيانات، ويضيف البيانات المرجعية الناقصة (الأدوار والقوائم). لا ينشئ أي مستخدم ولا يضيف أي بيانات تجريبية.

### المكونات (Docker Compose)
| الخدمة | الدور | البيانات الدائمة |
|---|---|---|
| `postgres` | PostgreSQL 16 | وحدة التخزين `pgdata` |
| `api` | الخادم (NestJS) + محرك PDF + أدوات النسخ الاحتياطي | `storage` (الملفات المرفوعة)، `backups` (النسخ المشفرة) |
| `web` | الواجهة (nginx)، وتمرّر `/api` إلى الخادم | — |

> لا تحذف وحدات التخزين (`docker compose down -v`) لأن ذلك يمحو كل البيانات.

## 2. HTTPS (موصى به بشدة)

دون HTTPS تعمل الواجهة على الشبكة المحلية، لكن مع قيود:
- لا يمكن تثبيت التطبيق كـ PWA، ولا فتح الواجهة دون اتصال: المتصفحات تشترط HTTPS لـ Service Worker.
- كلمات المرور والجلسات تمر غير مشفرة على الشبكة.

أبسط طريقة لـ HTTPS بنطاق عام هي وكيل عكسي مثل Caddy أمام المنفذ 8080:
```
assets.example.ma {
    reverse_proxy localhost:8080
}
```
بعدها اضبط `WEB_ORIGIN=https://assets.example.ma` و`COOKIE_SECURE=true` في `.env`، وأعد التشغيل بالأمر `docker compose ... up -d`.

---

## 3. النسخ الاحتياطي والاستعادة
- **الإعدادات ← النسخ الاحتياطي** (لمدير النظام): «إنشاء نسخة الآن»، «تحقق»، «تنزيل»، و«استعادة» (تتطلب كلمة المرور وعبارة التأكيد).
- النسخ مشفرة بالمفتاح `BACKUP_ENCRYPTION_KEY`. **إذا ضاع المفتاح فلا يمكن فتح أي نسخة**، فاحفظه في مكان آمن منفصل عن النسخ.
- النسخ تُحفظ على الخادم نفسه (وحدة `backups`). **نزّل نسخة دورياً واحفظها خارج الخادم** (قرص خارجي أو حاسوب آخر)، فالنسخ التلقائي إلى خارج الخادم غير متوفر.
- لا تُحذف النسخ القديمة تلقائياً: راقب المساحة واحذف القديم يدوياً من وحدة `backups` عند الحاجة.

---

## 4. التحديث إلى إصدار جديد
1. أنشئ نسخة احتياطية ونزّلها.
2. استبدل ملفات المشروع بالإصدار الجديد، مع الاحتفاظ بملف `.env`.
3. `docker compose -f docker/docker-compose.yml --env-file .env up -d --build`
4. تُطبَّق الترحيلات تلقائياً. تحقق بالأمر `curl …/api/v1/health` وبفتح الواجهة.

## 5. تطبيق Windows
1. شغّل `HassanAssets-Setup-1.0.0.exe`. يمكنك اختيار مجلد التثبيت، ويُضاف اختصار «التدبير المادي» إلى سطح المكتب وقائمة ابدأ.
2. **تحذير SmartScreen**: المثبّت غير موقّع بشهادة رقمية تجارية، فقد يظهر «Windows protected your PC». اضغط «More info» ثم «Run anyway». لإزالة التحذير يلزم شراء شهادة توقيع شيفرة (Code Signing) وإعادة البناء.
3. عند أول تشغيل، أدخل عنوان الخادم (مثل `http://192.168.1.10:8080`) ثم «اتصال». يتحقق التطبيق أن العنوان هو فعلاً خادم النظام قبل حفظه.
4. لتغيير الخادم لاحقاً: القائمة **التطبيق ← تغيير عنوان الخادم**.
- تُحفظ التقارير والملفات عبر نافذة «حفظ باسم» المعتادة، والطباعة عبر نافذة الطباعة في Windows.
- الإزالة من «إعدادات Windows ← التطبيقات». لا توجد بيانات للمؤسسة على الحاسوب.

## 6. تطبيق Android
1. انسخ `HassanAssets-1.0.0.apk` إلى الهاتف (أو نزّله)، وافتحه. اسمح بـ«تثبيت تطبيقات من مصادر غير معروفة» للتطبيق الذي فتحت منه الملف (مثل مدير الملفات أو المتصفح) عند الطلب.
2. أدخل عنوان الخادم ثم «اتصال». في كل تشغيل يتصل التطبيق تلقائياً بالخادم المحفوظ، مع زر «تغيير عنوان الخادم» يظهر لحظات قبل الاتصال.
3. يجب أن يكون الهاتف على شبكة المؤسسة (Wi-Fi) إذا كان الخادم محلياً.
- تقارير PDF وExcel تُحفظ في مجلد **التنزيلات** ثم تُفتح. الطباعة تمر عبر خدمة الطباعة في Android، ومنها «حفظ PDF».
- يقبل التطبيق خوادم http على الشبكة المحلية، ويوصى بـ HTTPS.
- **مفتاح توقيع التطبيق**: كل تحديث لاحق للتطبيق يجب أن يوقَّع بنفس المفتاح، وإلا رفض Android تثبيته فوق القديم. احفظ ملف المفتاح وكلمة مروره في مكان آمن، ولا تضعهما في Git.

## 7. المتصفح وتثبيت PWA
- افتح عنوان الخادم في Chrome أو Edge. مع HTTPS تظهر أيقونة «تثبيت التطبيق» في شريط العنوان، وعلى الهاتف «إضافة إلى الشاشة الرئيسية».
- تُخزَّن واجهة التطبيق فقط ليفتح بسرعة ودون اتصال. **لا تُخزَّن بيانات المؤسسة في المتصفح**، والعمليات المسجلة دون اتصال (صرف المخزون وإدخاله، وعدّ الجرد) ترسَل عند عودة الشبكة.

## 8. البناء من المصدر (للمطوّر)
| النسخة | الأمر | المخرج |
|---|---|---|
| الخادم والواجهة | `docker compose -f docker/docker-compose.yml build` | صورتان: `api` و`web` |
| Windows | `npm run build:windows` (يتطلب Docker؛ أو على Windows: `cd apps/desktop && npm ci && npm run build:win`) | `apps/desktop/dist/HassanAssets-Setup-1.0.0.exe` |
| Android | `HASSAN_SIGNING_DIR=<مجلد المفتاح> npm run build:android` (يتطلب Docker) | `apps/android/android/app/build/outputs/apk/release/app-release.apk` |

مجلد مفتاح Android يحتوي `hassan-release.jks` و`keystore.properties`:
```
storeFile=/signing/hassan-release.jks
storePassword=…
keyAlias=hassan
keyPassword=…
```
صفحة الاتصال المشتركة بين التطبيقين في `apps/shell/connect/`، وتُنسخ إليهما عند البناء.

### الاختبارات على النسخ المبنية
```bash
# الواجهة والخادم بعد docker compose up (قاعدة فارغة؛ LOGIN_RATE_LIMIT مرتفع للاختبار)
cd apps/web && DOCKER_BASE_URL=http://localhost:8080 npx playwright test -c playwright.docker.config.ts
# تطبيق Windows (الشيفرة نفسها مبنية لـ Linux، على شاشة افتراضية)
cd apps/desktop && SERVER_URL=http://localhost:8080 ADMIN_PASS=… xvfb-run -a node test/desktop.e2e.mjs --exe dist/linux-unpacked/HassanAssets
# الجزء الويب من تطبيق Android بمقاس هاتف
cd apps/android && SERVER_URL=http://localhost:8080 ADMIN_PASS=… node test/android-web.e2e.mjs
```

## 9. حل المشكلات
| المشكلة | الحل |
|---|---|
| الواجهة تفتح لكن الدخول يفشل أو يخرجك فوراً | تحقق من `COOKIE_SECURE`: يجب أن يكون `false` عبر http و`true` عبر HTTPS. وتحقق أن `WEB_ORIGIN` يطابق العنوان الذي تفتحه |
| «تعذّر الوصول إلى الخادم» في التطبيقين | تأكد أن الجهاز على نفس الشبكة، وأن المنفذ (8080) مفتوح في جدار الحماية، وأن العنوان يبدأ بـ `http://` أو `https://` الصحيح |
| زر النسخ الاحتياطي معطل | `BACKUP_ENCRYPTION_KEY` فارغ في `.env` |
| تقارير PDF لا تُولَّد | سجلات الخادم: `docker compose … logs api` (سطر `Chromium launch failed`) |
| بعد التحديث لا تظهر التغييرات | حدّث الصفحة (Ctrl+F5). التطبيق المثبّت كـ PWA يتحدث تلقائياً عند الفتح التالي |
